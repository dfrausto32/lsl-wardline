# Windows tunnel and installer hosting (task 2.0)

Decided by Dylan on 2026-10-28.

## Decision 1: drive the official WireGuard for Windows

The Windows agent does not carry its own tunnel code. It runs as a Windows service and uses the official WireGuard for Windows program that is installed on the computer:

- Install: the agent installer installs the official WireGuard MSI silently (the MSI supports the `DO_NOT_LAUNCH` property, so no WireGuard window appears for the person).
- Tunnel: the agent writes the rendered config to a file and runs `wireguard /installtunnelservice <file>` to create the tunnel service (`WireGuardTunnel$<name>`), and `/uninstalltunnelservice` to remove it. To change a running tunnel the agent uses the `wg` tool against it, so changes are applied without dropping the connection where possible.
- Config files: WireGuard encrypts a `.conf` it finds in its folder to `.conf.dpapi` readable only by the system account, and the agent deletes its own plaintext copy straight after use. The private key is generated by the agent on the computer and is never sent anywhere (BUSINESS-RULES, agent device).
- Why: least code, the signed driver and its updates stay with WireGuard, and the person ends up with a standard, recognisable tunnel.

Sources read: the WireGuard for Windows enterprise documentation (command line switches, DPAPI config handling, MSI properties) and the wireguard-nt and embeddable-dll-service READMEs (the alternatives, not chosen).
